# Recipes Book Bot

Telegram-бот для сайта [KobaLuck/Recipes](https://github.com/KobaLuck/Recipes):
просмотр рецептов без входа, регистрация и вход, создание рецептов,
избранное, корзина и объединённый список покупок.

## Установка и запуск

Требуется Python 3.9–3.12 и работающий API сайта Recipes.

```sh
git clone https://github.com/KobaLuck/recipe_bot.git
cd recipe_bot
python -m venv .venv
# macOS/Linux:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
cp .env.example .env
# Windows: Copy-Item .env.example .env
```

В `.env` задайте `TELEGRAM_BOT_TOKEN` от BotFather и `SITE_API_BASE`,
например `https://example.com/api/`. Файл загружается из папки проекта,
поэтому запуск из другого рабочего каталога тоже поддерживается.

```sh
python bot.py
```

Откройте личный чат с ботом и отправьте `/start`.
Бот обрабатывает только личные чаты, поскольку вход включает ввод пароля.
Сообщение с паролем удаляется, если Telegram разрешает удаление.
Пароль не сохраняется. Для входа используется токен сайта.

Команды: `/start`, `/menu`, `/add`, `/addrecipe`, `/cancel`.
`/start` и `/menu` сбрасывают незавершённый диалог. Черновики в памяти
теряются при перезапуске. `/cancel` и кнопка «Отмена» доступны на каждом шаге.
Для создания рецепта, избранного и корзины требуется вход.

Ингредиенты выбираются по букве или началу названия, с локальной пагинацией,
если API возвращает полный список. Количество и время — положительные целые
числа. Повторный ингредиент добавить нельзя.

Кнопка «Пропустить» для тегов выбирает первый тег сайта: API требует хотя бы
один тег. Если тегов нет, сначала добавьте их на сайте. При пропуске фото
отправляется изображение-заглушка, поскольку API требует изображение.
Ссылка на источник сохраняется в описании рецепта.

При ошибке сохранения черновик остаётся доступен для повтора или отмены.
Если соединение оборвалось после отправки, сначала проверьте список на сайте:
API не поддерживает ключи идемпотентности, и повтор запроса может создать дубликат.
После успешного сохранения повторное нажатие старой кнопки игнорируется.

## Хранение данных

Рецепты, ингредиенты, теги, избранное и корзина хранятся **на сайте Recipes**.
Бот не синхронизирует их с локальными Flask-моделями.

Токены входа хранятся в `instance/bot_user_tokens.json` (путь можно задать
через `TOKENS_FILE`). Файл записывается атомарно с доступом только владельцу
на Unix. Это локальное незашифрованное хранилище: ограничьте доступ к папке
и запускайте один экземпляр бота. Для выхода используется API сайта,
после чего локальный токен удаляется. Старый файл `bot_user_tokens.json`
можно перенести в `instance/` или указать его путь в `TOKENS_FILE`.

## Запуск без готового API на этом компьютере

Можно запустить бота и сервер Recipes вместе, на локальной SQLite-базе:

```sh
python -m pip install -r requirements-contract.txt
git clone https://github.com/KobaLuck/Recipes.git ../Recipes
python run_local.py --site-source ../Recipes/backend
```

Нужен только токен Telegram в `.env`. `run_local.py` переопределяет адрес API
для дочернего бота на `http://127.0.0.1:8765/api/`, создаёт базу
`instance/site/site.sqlite3`, загружает каталог ингредиентов и три тега.
Для Telegram не нужен публичный адрес API: бот забирает сообщения сам.
Фото для отправки в Telegram бот загружает через локальный API.

Остановка: Ctrl+C. База и токены сохраняются. Не запускайте второй экземпляр
одновременно. Бот работает, пока этот процесс запущен, компьютер включён,
не спит и подключён к интернету. Автозапуск при входе в систему не настраивается.
Этот режим использует старый сервер Recipes с совместимыми зависимостями;
сервер слушает только localhost и не предназначен для публичного размещения.

## Docker

```sh
docker compose up -d --build bot
```

Токены сохраняются в именованном томе `bot_data`. `.env` и локальные токены
исключены из образа. Для локального API из контейнера укажите доступный из
контейнера адрес (на Docker Desktop обычно `http://host.docker.internal:8000/api/`).

## Необязательная старая SQLite-админка

`app.py`, `models.py` и `init_db.py` оставлены для управления прежней локальной
базой. Это отдельные данные, не база сайта. Боту этот процесс не нужен.

```sh
python init_db.py
python app.py
# Или: docker compose --profile admin up -d --build
```

Папка SQLite создаётся автоматически. Можно задать `DATABASE_URL`;
относительные SQLite-пути разрешаются относительно Flask `instance/`.
Существующий файл базы удалять не нужно.

Админка: `http://127.0.0.1:5000/admin/`. Задайте `ADMIN_USERNAME` и
`ADMIN_PASSWORD` в `.env`; без них доступ отключён. По умолчанию сервер
слушает только локальный адрес. Для удалённого доступа нужны HTTPS и
отдельный сервер WSGI; встроенный Flask-сервер предназначен для разработки.

## Проверки

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
ruff check .
```

Тесты проходят через настоящий диспетчер python-telegram-bot и локальный
HTTP-сервер API. Внешний Telegram заменён тестовым транспортом: тесты не
отправляют сообщения реальным пользователям и не требуют секретов.

Дополнительно можно проверить бота с неизменённым серверным кодом Recipes,
используя временную SQLite-базу и тестовые изображения:

```sh
python -m pip install -r requirements-contract.txt
git clone https://github.com/KobaLuck/Recipes.git ../Recipes
SITE_SOURCE=../Recipes/backend python -m pytest tests/test_site_contract.py -q
```

Этот тест создаёт отдельную временную базу и не обращается к вашему рабочему сайту.
Совместимость с сервером проверена для коммита, указанного в `VALIDATION.md`.
